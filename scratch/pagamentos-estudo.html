01

Contexto e Premissas

O Academia Fight é um SaaS onde academias pagam pelo uso do app nas lojas (Apple/Google). O fluxo de pagamento que queremos implementar é diferente: é o aluno pagando a academia pelo app — mensalidades, matrículas, graduações, taxas de material.

O app age como plataforma facilitadora, não como intermediário financeiro. Não há split de receita para o Academia Fight — a academia recebe 100% do valor pago pelo aluno (menos a taxa do provedor de pagamentos, que é cobrada da academia, não de nós).

Premissa central Definido

Academia Fight não recebe comissão sobre pagamentos entre alunos e academias. A academia é o recebedor final. O provedor de pagamentos cobra taxa diretamente da academia (ou do valor recebido). Nosso negócio é o SaaS — não processamento de pagamentos.

Modelo de conta da academia

Cada academia cadastrada no sistema precisa ter uma subconta no provedor (Asaas chama de "conta digital"). O Academia Fight terá uma conta principal (Master) e cada academia vinculada terá sua subconta. Todo pagamento de aluno vai direto para a subconta da academia correspondente.

Onboarding da academia Implementação

Ao ativar pagamentos, a academia preenche seus dados (CNPJ ou CPF, banco, dados pessoais do responsável) diretamente na tela do app admin. O Asaas faz o KYC (verificação de identidade) automaticamente. Após aprovação, a academia recebe um subAccountId armazenado no Firestore.

Recomendação: Asaas Recomendado

Por quê Asaas? É o provedor mais amigável para o modelo marketplace no Brasil. Tem API REST simples, subcontas nativas, PIX integrado, boleto, cartão de crédito/débito, recorrência automática e KYC automático para as academias. O Iugu é uma boa segunda opção se o Asaas apresentar algum bloqueio contratual — a arquitetura seria idêntica.

04

Métodos de Pagamento

PIX — Prioridade 1

PIX (pagamento instantâneo) Alta prioridade

O aluno toca em "Pagar" → Cloud Function solicita ao Asaas um QR Code PIX para a subconta da academia → app exibe o QR Code e a chave copia-e-cola → aluno paga pelo banco → Asaas detecta o pagamento e dispara webhook → Cloud Function atualiza o Firestore → aluno vê "Pago" em tempo real via stream do Firestore.

Taxa Asaas: geralmente R$ 1,99 por PIX recebido (cobrado da academia). Zero pra nós.

Cartão de crédito — Prioridade 2

Cartão (avulso ou recorrente) Implementação

O aluno digita os dados do cartão diretamente no SDK do Asaas (nunca passam pelo nosso servidor — PCI DSS). O Asaas gera um token (creditCardToken) que armazenamos no Firestore vinculado ao aluno. Para mensalidades recorrentes, o Asaas gerencia automaticamente as cobranças mensais e dispara webhooks de sucesso/falha.

Taxa Asaas: ~2,49% + R$ 0,49 por transação de crédito (cobrado da academia).

O que não implementar (por ora)

Boleto bancário: alta taxa de inadimplência, compensação em D+2, gera complexidade operacional. Descartado na v1.

Débito em conta: requer autorização do banco do aluno, muito fricção. Descartado na v1.
05

Arquitetura Técnica

O app mobile nunca chama o Asaas diretamente. Toda comunicação com o provedor passa por Cloud Functions, que atuam como camada de segurança e orquestração.

Componentes novos no sistema

  • 1
    Cloud Functions — Gateway de Pagamento
    Funções: criarCobrancaPix, criarCobrancaCartao, salvarCartao, cancelarCobranca, webhookAsaas. Guardam a API Key do Asaas em Secret Manager — nunca exposta ao cliente.
  • 2
    Firestore — Novas coleções
    academias/{id}/asaas (subAccountId, status KYC), academias/{id}/pagamentos_metodos (tokens de cartão por aluno), academias/{id}/transacoes (registro de cada cobrança do Asaas com status).
  • 3
    Webhook Endpoint
    URL pública (Cloud Function) que o Asaas chama quando um pagamento muda de status. Valida a assinatura do Asaas (asaas-access-token no header), atualiza o documento de pagamentos no Firestore e notifica o aluno via FCM se necessário.
  • 4
    Secret Manager (Google Cloud)
    API Key do Asaas, token de validação de webhook e quaisquer segredos ficam no Secret Manager — acessados apenas pelas Cloud Functions em runtime, nunca hardcoded nem em variáveis de ambiente visíveis.

Fluxo detalhado — PIX

  • 1
    Aluno toca em "Pagar via PIX"
    App chama criarCobrancaPix({pagamentoId, academiaId}) via Firebase callable function.
  • 2
    Cloud Function cria cobrança
    Busca o subAccountId da academia, chama API do Asaas com valor, vencimento e dados do aluno. Asaas retorna QR Code e payload PIX.
  • 3
    App exibe QR Code
    Salva o asaasChargeId no documento do pagamento. Aluno paga no banco. App faz stream do documento — quando o status muda para "pago", exibe confirmação.
  • 4
    Asaas dispara webhook
    Cloud Function webhookAsaas valida a assinatura, encontra o pagamento pelo asaasChargeId, atualiza status: 1 (Pago) no Firestore.
06

Segurança

Pagamentos exigem atenção redobrada. Aqui estão todos os vetores de risco e como cada um é mitigado.

🔐
Dados de cartão — PCI DSS
Risco: alto. Se dados de cartão passarem pelos nossos servidores, precisamos de auditoria PCI DSS completa (custo alto, processo longo).
Mitigação: O aluno digita o cartão diretamente no SDK do Asaas (tokenização no lado do cliente). Nosso servidor recebe apenas o creditCardToken — nunca o número do cartão, CVV ou validade. O Asaas é PCI DSS nível 1.
🔑
Exposição da API Key do Asaas
Risco: alto. API Key exposta = acesso irrestrito a todas as subcontas.
Mitigação: API Key armazenada exclusivamente no Secret Manager do Google Cloud. Nenhuma variável de ambiente em código, nenhum arquivo .env commitado. Acesso somente pelas Cloud Functions em runtime.
🪝
Webhook falso (spoofing)
Risco: alto. Um atacante poderia enviar um webhook falso marcando pagamentos como pagos sem que o aluno pagasse.
Mitigação: Validar o header asaas-access-token em toda requisição webhook. Rejeitar imediatamente qualquer chamada sem token válido. Nunca processar webhooks de IPs não documentados pelo Asaas (whitelist opcional).
🔒
Regras do Firestore — isolamento de dados
Risco: médio. Aluno A acessar dados financeiros do Aluno B, ou academia X ver dados da academia Y.
Mitigação: Security Rules do Firestore: aluno só lê/escreve nos seus próprios documentos de pagamento. Admin só acessa documentos da sua academia. Cloud Functions usam Admin SDK (bypass de rules) — devem validar academiaId do contexto de autenticação antes de qualquer operação.
🛡️
LGPD — dados financeiros
Risco: médio. Dados de pagamento são dados sensíveis sob a LGPD.
Mitigação: Armazenar apenas o necessário: token do cartão (não dados brutos), histórico de pagamentos da academia. Exibir consentimento explícito ao aluno ao salvar cartão. Permitir exclusão do token a qualquer momento. Documentar na Política de Privacidade.
🔄
Dupla cobrança / idempotência
Risco: baixo-médio. Retry de network pode criar duas cobranças para o mesmo pagamento.
Mitigação: Enviar externalReference: pagamentoId em toda cobrança. Antes de criar, verificar se já existe cobrança ativa com aquele ID. Asaas suporta idempotência por referência externa.
📱
Man-in-the-middle no app
Risco: baixo. App Flutter usa HTTPS obrigatório. Cloud Functions são HTTPS by default. QR Code PIX é exibido localmente — sem transmissão de dados sensíveis pelo app.

Impacto no App

App Admin (academia)

  • →
    Nova tela: Configurar Recebimentos
    Formulário de onboarding Asaas (CPF/CNPJ, dados bancários, responsável). Mostra status do KYC ("Pendente", "Aprovado", "Rejeitado"). Exibe saldo disponível na subconta.
  • →
    Financeiro — sem mudança visual
    A tela atual de cobranças continua igual. Só adicionamos um badge "Pago via PIX/Cartão" e o asaasChargeId fica armazenado internamente. O admin não precisa fazer nada extra — o webhook atualiza tudo automaticamente.

App do Aluno

  • →
    Nova seção: Financeiro do Aluno
    Lista de cobranças pendentes/pagas. Botões "Pagar via PIX" e "Pagar com Cartão" em cada cobrança pendente.
  • →
    Tela de pagamento PIX
    QR Code em destaque + botão "Copiar chave". Timer de expiração (30 min). Polling/stream no Firestore para confirmar pagamento em tempo real.
  • →
    Tela de pagamento por cartão
    Campo nome, número, validade, CVV — renderizados pelo SDK do Asaas (WebView segura). Opção "Salvar cartão para próximas cobranças". Se cartão salvo: lista os cartões disponíveis e permite pagar com 1 toque.
  • →
    Mensalidade recorrente
    Ao ativar recorrência, o Asaas cobra automaticamente no dia de vencimento configurado pelo admin. O aluno recebe push notification quando a cobrança é criada e quando é confirmada.

Taxas e Custos

O Asaas não é gratuito — cobra taxas por transação processada. A boa notícia: quem paga a taxa é a academia (ou o aluno, dependendo da decisão abaixo), nunca o Academia Fight. Abaixo estão as taxas vigentes para o modelo subconta/marketplace.

Aviso importante

As taxas abaixo são baseadas na tabela pública do Asaas e estão sujeitas a alteração. Confirme os valores vigentes em asaas.com/precos antes de tomar decisões financeiras. Para subcontas, o Asaas pode negociar taxas menores conforme o volume mensal de transações da plataforma.

Tabela de taxas por método de pagamento

Método Taxa por transação Quem paga Quando é debitado
PIX ~R$ 1,99 fixo ou ~0,99% (plano volume) Subconta da academia No momento do recebimento
Cartão de crédito (à vista) ~2,99% do valor Subconta da academia Na liquidação (D+30)
Cartão de crédito (2–12x) ~3,49% + juros de parcelamento Subconta da academia Na liquidação de cada parcela
Cartão de débito ~1,99% Subconta da academia Na liquidação (D+1)
Boleto bancário R$ 1,99 a R$ 3,49 (por emissão) Subconta da academia No pagamento do boleto
Saque PIX (subconta → banco) Gratuito ou ~R$ 0,50 Subconta da academia No momento do saque
Saque TED (subconta → banco) ~R$ 2,00 a R$ 5,00 Subconta da academia No momento do saque
Taxa do Academia Fight R$ 0,00 — Nunca cobramos comissão

Decisão: quem arca com a taxa? Validar com sócio

Existem 3 modelos possíveis:

🏫
Opção A — Academia absorve (recomendado)
A taxa é descontada do valor que a academia recebe. O aluno paga R$ 250 e a academia recebe R$ 248,01 no PIX. Mais simples de implementar. Academias já pagam taxa de maquininha (geralmente 1,5% a 3,5%) — é um modelo familiar. Bom argumento: "com nossa maquininha você ia perder R$ 8, com o app perde só R$ 2 via PIX".
👨‍🎓
Opção B — Aluno paga a taxa de conveniência
A academia recebe o valor cheio. O aluno vê "R$ 250,00 + R$ 1,99 de taxa de conveniência". Requer lógica extra no app para calcular e exibir o breakdown. O aluno pode preferir pagar no dinheiro para evitar a taxa — pode reduzir adoção.
❌
Opção C — Academia Fight absorve
Nós bancamos as taxas do nosso próprio caixa. Não recomendado. Em 100 academias com 30 alunos cada pagando R$ 1,99/mês de PIX, são ~R$ 6.000/mês em taxas que sairíamos do nosso bolso sem retorno.

Conta Master do Academia Fight no Asaas

A conta principal (Master) precisa ser mantida. O Asaas pode cobrar uma mensalidade da conta Master dependendo do volume de transações — geralmente isenta a partir de certo volume mensal. Verifique as condições em asaas.com/precos durante o onboarding. Para MVP (fase 1 com poucas academias), pode haver uma taxa fixa mensal baixa (~R$ 50–200/mês), que desaparece conforme o volume cresce.
